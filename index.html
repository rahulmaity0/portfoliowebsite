  1. Ledger & inventory

    Jewellery Ledger & Inventory System

    The backend that runs the books of a working gold manufacturing business — my family's.

    • One @Transactional method updates the locker inventory and the client's balance together, so the two can't drift apart.
    • Making charge is modelled as a purity uplift: the client is billed at purity plus charge, but the locker only loses the metal that actually left. The gap between them is the margin.
    • BigDecimal with HALF_UP throughout, and two rules checked rather than assumed — no issue beyond locker stock, no receipt beyond what's owed.
    • REST endpoints for clients, per-client ledgers, a dashboard and a monthly JPA report, behind stateless JWT auth.

    POST /api/transactions @Transactional locker + client balance invariant checks ledger

    • Spring Boot
    • Spring Security
    • JWT + BCrypt
    • JPA / Hibernate
    • BigDecimal

  2. SDET

    Payments API Test Automation Framework

    A Spring Boot payments API and the REST Assured suite that tests it. I wrote both sides.

    • An API client, reusable request specs, request models, a test-data factory and a shared base class keep the HTTP setup out of the test classes, so those only hold assertions.
    • The tests go after the cases that cost money: duplicate payments that must stay idempotent, insufficient funds, and high-value payments held for fraud review.
    • Runs against a real embedded server on a random port, and GitHub Actions publishes an Allure report on every push.

    test request spec payments API contract + negative assertions Allure in CI

    • REST Assured
    • JUnit 5
    • Allure
    • GitHub Actions
    • JSON Schema

  3. Web service

    URL Shortener Service

    Long URLs in, six-character codes out, with a click count on every link.

    • Codes are six base62 characters, so about 56 billion of them. Each one is checked against the database before use, and after ten tries it gives up rather than looping forever.
    • Click counts go up through JPA dirty checking inside a transaction instead of an explicit save call.
    • Bean Validation throws out malformed URLs before they ever reach the service layer.

    POST /api/urls base62 code collision check 302 + Location click count

    • Spring Boot
    • JPA / Hibernate
    • Bean Validation
    • JUnit 5
    • MockMvc
